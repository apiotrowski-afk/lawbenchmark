# verification/ — the verification layer

Two steps run before any model judge (report *Benchmark 02*, chapter 7): the **citation check** (code: `tools/verification/fakty.py`, every cited provision/ruling looked up in ISAP/ELI, SAOS, sn.pl via legal-cite-pl) and the **support check** (model: `tools/verification/poparcie.py`, does the cited source support the claim). Machine-readable form of the citation check: `data/verification.jsonl`.

## `reports/` — one report per answer (320 files)

`reports/<question>_<system>_r3.json` and `.md` — one pair per answer (10 questions × 16 systems): the citation-check report that the "card meta" judges received (`judges/*meta*`). Generated by `fakty.py`; `data/verification.jsonl` is built from the `.json` files.

## `runs/` — aggregate runs (15 files)

Files that cover many answers. Dated runs are kept side by side because the report compares them (before/after the scoring decisions of 24 October 2026). `.json` = per-citation detail, `.md` = summary that `dane.py` parses.

## Re-running

The scripts are published as used. The citation check needs [legal-cite-pl](https://github.com/apiotrowski-afk/legal-cite-pl); the support check needs Vertex AI access and, for ruling theses, an internal case-law database reached through a read-only gateway that is not part of this repository (`fakty.py`, `poparcie.py` import it from a path given in the environment; without it the ruling branch is skipped and reported as `tekst_niedostepny`).
